Principle_RF_Engineer_Agent — pipeline map, read from the code

The options chain, start to finish

This is what the agent actually does today, stage by stage, when it walks a requirement from prose to a batch of scored candidate designs — traced from the running code (orchestration/design_loop.py, orchestration/solver.py), not from the roadmap or the ADR prose, per this repo's own rule that planning docs are a plan someone wrote once, not a status report. Solid outlines are built and wired today. Dashed outlines are wired but incomplete. Dotted outlines are decisions an ADR already made that no code implements yet — switch them on to see exactly where each one would plug in.

A requirement enters at Requirements and can only leave, iteration after iteration, through Redesign Decision — the one place anything is actually written to the database. Three steps carry a padlock: Architecture, Measurement, and Redesign Decision itself. None of the three can be crossed without a signed, human-bound approval receipt — not another AI role checking the first one's work, on purpose (that idea was considered and rejected: see ADR-0009).
Once one architecture is approved, the model can propose a whole batch of parameter guesses at once — that batch, run through run_candidate_search, is the actual "options chain." Each guess runs Analysis, Simulation and Optimization on its own; lane 3 above fails partway through and is simply marked failed and skipped — it never aborts the other three. The batch stops the moment one guess satisfies the target, or the running best score stalls (a plateau), or the evaluation budget runs out, or the loop reaches a step that needs a human — and it always records which of those four reasons applied.
Choose reflection-phase steering or diffusive scattering at Architecture, and neither family declares a full-wave solver in the registry. Simulation quietly falls back to a thin-wire, method-of-moments solver built for antennas made of wires — the wrong physics for a periodic surface — and nothing raises an error to say so. It is the quietest gap in the pipeline today, which is exactly why it is worth knowing about.
Every dotted outline on this page is a decision an ADR already made in writing, with no code behind it yet — from a literature search that can actually search instead of only fetching a citation you already have, to a library of shapes that were printed and measured rather than only simulated, to a person's "yes" having anywhere to actually land. Turn the toggle on above, and follow each dotted line to the exact box it would sit beside.

01

Requirement intake

Built

design_loop.py:382 · designs/service.py:54

create_designstart_new_design_loop

Decides: records the customer's stated requirement, word for word, as the loop's first decision, and opens a real database row for the design.

Why: nothing here reads intent yet — that comes next. This step exists so the original prose survives untouched and tagged ASSUMED, so later stages can be checked against what was actually asked for, not a paraphrase of it.

01a

Requirement → target

Built

requirement_targets.py:186, 202, 210, 301

propose_requirement_targetconfirm_requirement_targetmark_requirement_unscoreable

Decides: turns prose ("needs to work at 2.4 GHz without losing gain") into a number, a comparator (at-least / at-most / equals), a unit, and an optional tolerance.

Why: the one module named directly in this project's own charter — it never calls an LLM. It only checks the number the model proposed is finite and the unit isn't blank; the judgment about what the requirement means stays with the model, the code just checks the paperwork is filled in. Even after a human confirms the target it stays ASSUMED forever — confirming a reading of prose makes it more trusted, not a different kind of evidence.

02

Architecture

Built · gated

design_loop.py:456 · design_families.py

advance_design_loop_step

Decides: commits this iteration to exactly one of six design families — patch, absorber, transmissive absorber, reflection-phase steering, diffusive scattering, or polarization conversion.

Why: the pipeline deliberately does not auto-generate several architectures and silently rank-pick the best-scoring one — a human has to see and approve the one being tried (ADR-0014). One of only three places in the whole loop where a human's yes is required before anything proceeds.

Precedent search — local corpus

Built

knowledge/search.py

search_knowledgesearch_design_records

Decides: looks for a prior design, patent, or paper already sitting in the project's own database before letting the model invent something new.

Why: keyword plus meaning-based (embedding) search over what's already been read in genuinely works. What it can't do yet is go and find something nobody has fed in first — see the partial and proposed cards below.

03

Analysis — closed form

Built

design_loop.py:600 · rf_tools/absorber.py · rf_tools/sheet_impedance.py

internal — driven by the loop & the solver

Decides: a cheap, pencil-and-paper-grade estimate — for an absorber, the single worst-absorbing frequency in the required band from an equivalent-circuit model (Costa/Luukkonen); for a patch, its resonant frequency from the closed-form patch formula.

Why: the "evaluate cheap before expensive" tier this project's method calls for. For absorbers it also runs the Rozanov thickness-versus-bandwidth limit as a real number, not just a comment, so a physically impossible design is caught before a solver ever sees it.

04

Simulation — full wave

Built

design_loop.py:748 · simulation/nec2pp.py · simulation/meep.py

run_nec2_simulationrun_meep_simulation+11 more standalone adapters

Decides: a physically grounded confirmation of the cheap guess — method-of-moments for a patch antenna (NEC2), FDTD with periodic boundaries for an absorber sheet (MEEP).

Why: confirms or contradicts the closed-form estimate before money or bench time is spent. Thirteen solver adapters exist in this codebase (openEMS, HFSS, Palace, Elmer, and more), but the loop only auto-wires two of them today — see the partial cards for exactly where that falls short.

05

Optimization

Built

design_loop.py:919 · optimization/rf_objectives.py

optimize_patch_length_for_target_frequency

Decides: searches one parameter — patch length — to hit the target frequency, by Bayesian search by default, or grid / genetic / gradient on request.

Why: only wired for the patch family today. A search over which pre-characterised shape sits in which cell is the natural optimizer for the metasurface families — it has a name reserved for it (COMBINATORIAL) and nothing behind it yet.

05'

run_candidate_search — the options chain

Built

orchestration/solver.py

run_candidate_search

Decides: drives a whole batch of the model's proposed parameter sets through Analysis → Simulation → Optimization, scores every one, and hands back the ranked batch plus its pick of the best.

Why: a candidate is scored by its single worst-performing requirement, never an average — "the design is only as good as its worst-performing stated requirement." The batch stops on hitting the target, on the score plateauing, on running out of its evaluation budget, or on reaching a step that needs a human — and always says which, so a budget running out is never mistaken for a design being finished.

05a

success_score

Built

designs/success_score.py:320, 348, 448

internal — called by run_candidate_search

Decides: how close one numeric result sits to its target — non-linear and bounded, so overshooting a threshold isn't extra credit.

Why: every score carries two separate flags — how the target was obtained (always ASSUMED, read from prose) and whether a human has confirmed it (PROPOSED or CONFIRMED). Keeping those separate stops a score against an unreviewed guess from ever being confused with a score against something a person actually checked.

Verification

Built

design_loop.py:940

verify_requirement

Decides: compiles one row per requirement — expected value, actual value, pass / fail / conditional pass / blocked — from the evidence already on record.

Why: not gated. Summarising evidence that already exists isn't a judgment call that needs a human's sign-off; approving what to do about it, later, is.

06'

Lab test plan

Built

orchestration/lab_test_plan.py:765, 849

compile_lab_test_plan

Decides: before a bench trip — what to measure, by what method, and what this iteration already predicts the answer is, plus a plain list of which requirements can't be checked at all, and exactly why.

Why: this is "when stuck, name the missing measurement," actually built. Four named reasons cover every case a requirement is unverifiable, so a trip to the lab confirms a stated guess instead of going fishing.

07

Measurement

Built · gated

design_loop.py:955 · measurement/external.py

advance_design_loop_step(touchstone_file=...)

Decides: accepts one Touchstone file (.sNp) measured on real, independent bench equipment as evidence.

Why: there is no instrument control anywhere in this codebase, on purpose — a file someone measured and physically brought back is the only way anything earns the top-ranked MEASURED label. Also one of the three gates: a human decides this measurement is accepted evidence for this design.

08

Correlation

Built

design_loop.py:1017 · rf_tools/correlation.py:314

correlate_simulated_and_measured

Decides: a number — how far the simulated prediction sits from what was actually measured, per S-parameter (worst-case dB difference, RMS difference).

Why: half of "compare prediction against result," fully built as arithmetic. The other half — whether the model's physics or the fabricated part is what broke — stays a written judgment call at the next step, not a computed verdict. See the proposed card below for the trade-off.

09

Redesign decision

Built · gated

design_loop.py:1050 · tooling.py:294

advance_design_loop_step

Decides: iterate (loop back to Architecture, iteration count up by one) or accept the design. There is no third "release it" option anywhere in the code.

Why: the only point in the whole loop where anything is actually written to the database — one transaction, everything recorded since this step last fired. A test in the repo proves structurally that nothing can skip straight from here to manufacture.

The human-approval gate

Built · unwired

orchestration/approval.py · designs/release_approval.py

request_loop_step_approvalrequest_design_release_approval

Decides: whether a given Architecture / Measurement / Redesign-decision / Release step is actually allowed to happen.

Why: the program's one hard stop — "no print, no order, no release without a human saying yes" — built as a signed receipt tied to the exact decision it approves, so it can't be replayed against a different one. Today, though, nothing in the repository connects it to an actual person: the callback defaults to nothing, and calling it with nothing always refuses. That's the intended fail-safe, not a bug — but it also means a design can't be walked past Architecture at all in an unmodified deployment. See the proposed card below.

Proposed — no code yet

decisions an ADR already made, with nothing built behind them

Open-literature discovery search

Planned

Lands: right after Architecture, beside precedent search

Would decide: a query-based search across patents, arXiv and standards — "find me a shape that does X" — rather than only "fetch this ID I already have."

Why: closes the gap named above, and makes "search precedent before inventing" actually mean searching, not just recalling what's already stored.

Element / Coding-Alphabet library

Planned

Lands: between Architecture and Analysis, feeding metasurface candidate generation

Would decide: which pre-characterised shapes ("letters") are available to place, keyed by shape, band, incidence angle and the exact process (machine, ink, cure) that made them.

Why: the whole argument of ADR-0027 is that a library only worth trusting is built from letters that were actually printed and measured, not simulated — the project's stated point of difference from every other metasurface library. There's no table for it today: no schema, no store, just a function that expects the caller to already hand it a finished dictionary of shapes. Filling this in is named, in the program's own charter, as its very first job.

Prediction + mechanism claim, per batch

Planned

Lands: inside run_candidate_search, in the same call that proposes each candidate

Would decide: one predicted value per candidate, plus one stated reason for the whole batch — written down before Analysis runs, not after.

Why: ADR-0022's argument — a batch of guesses that land in the right ballpark for the wrong reason still teaches nothing. Recording the guess and the reason for it before the answer is known is what turns four hundred failed candidates into a sortable dataset instead of noise. Designed to never block a run — an absence would just be recorded, not refused.

A real Tier-B solver

Planned

Lands: design_families.py's registry entries for reflection-phase & diffusive

Would decide: the full-wave engine those two families actually simulate against.

Why: Palace already exists in this codebase with native periodic (Floquet) ports, and is validated against Palace's own published results to within 0.056 dB — sitting there unused by the loop. Pointing the registry at it (or openEMS) instead of the silent NEC2 fallback turns an un-flagged wrong answer into either a right one or an honest refusal.

Combinatorial (symbol-placement) optimizer

Planned

Lands: Optimization, Tier-B families only

Would decide: which pre-characterised letter sits in which cell of the array, searched rather than hand-placed.

Why: already named as a value in the registry; nothing implements it, and it depends on the alphabet above existing first.

Structured attribution

Planned

Lands: between Correlation and Redesign Decision

Would decide: a simple tag alongside the free text — was the mismatch the model's physics, or the fabricated part?

Why: would make that judgment call searchable across a project's history instead of buried in prose. Worth weighing against this project's own stance that it deliberately doesn't over-formalize a judgment call that's still a human's to make — offered here as a real trade-off, not a clear win.

A real approval callback

Planned

Lands: wherever a gate sits — Architecture, Measurement, Redesign Decision, Release

Would decide: how an actual human's "yes" reaches the gate — a CLI prompt, a Slack message, a small web form.

Why: the gate mechanism itself is real and already tamper-evident; nothing is on the other end of it. Without this, every gated step refuses unconditionally — safe, but it also means the loop can't currently be walked end to end even for a design a person is ready to approve.
