Does the design loop survive the model re-entering between batches?

A throwaway demo for issue #224, under map #104. Press the buttons and watch the state change. Nothing here is production code.

The question. Today run_candidate_search drives one batch of ideas the model handed it, then stops and returns a report. We want the model to read that report, think up a better batch, and go round again — overnight, with nobody watching. Does the machinery underneath allow that?

In plain terms: the machine currently tries a list someone gave it and stops. We want it to write its own next list and keep going. This demo pushes the real step rules through that loop to see what breaks.

Every rule below is lifted from the real modules — DesignStep, STEP_ORDER, GATED_STEPS (orchestration/design_loop.py), _ORDERED_UNGATED_SPAN, _steps_from, _drive_candidate, run_candidate_search (orchestration/solver.py). The physics is stubbed: scores come from a fixed table so every walkthrough runs the same way twice. No claim here is about antennas. It is about sequencing, gates and records.
